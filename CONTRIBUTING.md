# Contributing

This guide lists the rules that already apply in the repository. `CLAUDE.md` is the full reference (decisions, verified facts, open points); `.github/copilot-instructions.md` repeats its essential rules.

## Development environment

- The repository provides a devcontainer (`.devcontainer/`), with the same tool versions as the CI (Node 20, Python 3.12, PyYAML 6.0.4). See the section "Development environment (sandbox)" of the [README](README.md).
- **Before opening it for the first time, set up the host machine by following [docs/DEVCONTAINER_SECURITY.md](docs/DEVCONTAINER_SECURITY.md)**: part of the isolation (git credentials, SSH agent) cannot be set from the repository.
- In the container, git is read-only: commits and pushes are made from the host machine, after review of the diff.

## Checks and pull requests

- Run `tools/ci.sh` before every commit: it runs locally the same checks as the GitHub CI (tests, ES5, template up to date, template structure).
- Every change to `main` goes through a pull request. The check `tests` (GitHub CI) is required on `main`.

## Code

- **Generated template**: `templates/*.yaml` is generated by `tools/generate_templates.py`: never edit it by hand. Change `src/collector.js` or the generator, then run `python3 tools/generate_templates.py`. The CI fails if the committed template is out of sync with `src/collector.js`.
- **ES5**: `src/collector.js` must stay ES5 (Zabbix runs it in Duktape): no `let`, `const`, arrow functions or template strings. The CI checks it.
- **65,535 characters**: Zabbix limits item scripts to 65,535 characters. The template embeds a comment-stripped copy of `src/collector.js`: keep new code compact, and keep the comments in the source. The generator, `tools/validate_template.py` and `tests/embedded_script.test.js` fail above the limit.
- **No inferred metric name**: every Druid field and dataSource queried must be in `docs/intersight_metrics.json`, the catalog extracted from the Intersight "Supported Metrics" pages. `tests/documented_fields.test.js` fails on any other field or dataSource. Computations must also be documented, or follow from documented definitions.
- **Base units**: store W, Wh, g, s, bps, B (data sizes), never kWh, kg, ms or KB. Convert source values to the base unit (ms → s, throughput bytes → bits, 0–1 ratios → %), never a base-unit value to a prefixed unit. Zabbix only adds the K/M/G prefixes on display (see the section "Units" of the [README](README.md)). `tests/units.test.js` rejects any other unit.
- **New item key when the unit changes**: a unit or scale change requires a new item key (new UUID, new series). With the same key, the old history would be read in the new unit. Note the old and new keys in the CHANGELOG, with the instruction to tick "Delete missing" for items on re-import (Zabbix 7.0 doc, "Import rules"): otherwise, the old items are not deleted.

## Tests

- New behaviour gets a PASS/FAIL check that sets `process.exitCode = 1` on failure. `node tests/run_all.js` runs every `tests/*.test.js` file.
- Never build a RegExp from a string in tests (CodeQL "Incomplete string escaping"): use plain text search (`indexOf` / `includes`).

## Documentation

- The README, the CONTRIBUTING guide and the guides of `docs/` exist in English and in French: every change is made in both languages, in the same pull request. Each file links to the other language.
- The CHANGELOG is in English only.
- Code and code comments are in English.

## Never commit

- `params.json` (parameters and private key for `zabbix_js`);
- credentials (`*.pem`, `*.key`, `.env`, `.env.*`);
- the `cisco-docs/` folder and `Supported_Metrices.md` (Cisco documentation, not redistributable);
- `docs/Zabbix_Documentation_*.pdf` (Zabbix manual, whose copyright notice forbids redistribution).

All of them are in `.gitignore`.

## Reporting a vulnerability

Never through a public issue: use GitHub's private vulnerability reporting, described in [SECURITY.md](SECURITY.md).
